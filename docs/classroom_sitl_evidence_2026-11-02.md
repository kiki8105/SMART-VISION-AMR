# 2026-11-02 classroom SITL evidence

All trials below used headless Gazebo, `ROS_DOMAIN_ID=176`, `ROS_LOCALHOST_ONLY=1`, and a dedicated localhost Gazebo master. They did not connect to the physical robot in domain 16. Early trials were navigation diagnostics; later web-owned trials exercised the delivery workflow. None is physical-robot acceptance.

## Latest web-owned integrated trials

The web-owned stages start one mission server on local port 8792, explicitly reset the independent EKF sensor guard and motion mux after healthy input, and run A* planning, Nav2 following, rear ArUco centering, 5-second stationary dwell at each sector, and Home return with the incident recorder enabled. A separate read-only monitor on 8791 publishes no robot commands.

The v6 run did pause at Sector 3 after a follower `execution_no_progress` event. The directed failed-approach memory held the only narrow route for about 120 seconds, then expired; the original web goal was retained and the robot resumed, completed Sector 3, and returned Home. A subsequent follower turn-progress correction and a bounded planner fallback were tested with focused unit suites and apply only to **new processes**. The v6 PASS proves completion with recovery, not that the new correction removed this wait. The Home moving-obstacle trials above did not pass full acceptance; Stage 17 remains unrun.

The simulator uses the checked-in physical Nav2, classroom node, and EKF YAML values except `use_sim_time`; the physical Nav2 YAML had two mixed-clock entries that were corrected to false before the latest stress runs. The simulator still differs from the robot in motor/OpenCR behavior, Wi-Fi scheduling, camera resolution/frame rate, battery guard, and placement of robot-local nodes. Runtime parameter equality on an actual robot requires a live `ros2 param dump` and physical testing.

The A/B result does not isolate the incident recorder as the sole cause: other CPU work also differed. `record_incidents:=true` is the current hardware launch default, so recorder-off SITL cannot be claimed as physical-equivalent performance. The runtime manifest records the selected profile for new trials.

The red cells occurred **before** any injected Home obstacle; they do not prove the requested inserted-obstacle appearance/disappearance behavior. Browser inspection showed the route SVG and both camera images. The raw-map and cleaned-map overlays still need a synchronized injected-obstacle test.
