# 강의실 실측 지도 기반 Gazebo 재현

2026-10-30에 새로 매핑한 강의실 지도를 원래 좌표계 그대로 사용한다. 지도 크기는 **86 × 140셀**, 해상도는 **5 cm/셀**, 원점은 **(-1.65, -5.25)**이다. 예전 `simulation_room.world`의 넓고 반듯한 통로를 사용하지 않는다. 실차에서 막혔던 좁은 통로와 파티션 간격을 지도 해상도대로 충돌 형상에 반영한다.

```bash
cd ~/Team2_workspace/src/SMART-VISION-AMR
./scripts/run_classroom_replay_sim.sh gui:=false
```

Gazebo 화면을 직접 보려면 `gui:=true`로 실행한다. 별도 터미널에서 다음 명령을
실행하면 실제 교실 지도·마커 좌표를 쓰는 웹 운용지도도 함께 볼 수 있다. 웹은
Gazebo와 같은 격리 도메인 76에만 연결되며 기본 주소는
`http://127.0.0.1:8791/`이다. 실차 웹(도메인 16, 포트 8790)과 설정 파일도
분리되어 있다.

```bash
cd ~/Team2_workspace/src/SMART-VISION-AMR
./scripts/run_classroom_replay_web.sh
```

웹 운용 화면은 실차와 동일하게 **후방 카메라만 기본 표시**한다. Gazebo의
`/camera/front/image_raw` 토픽 자체는 시뮬레이터에 남아 있지만 웹에서는
기본으로 구독하지 않는다. 전방 보조 화면이 필요한 별도 시험에서만
`SMART_VISION_CLASSROOM_SIM_FRONT_CAMERA_TOPIC=/camera/front/image_raw/compressed`
환경변수를 지정해 웹을 실행한다. 섹터 도착 확인은 언제나 후방 ArUco 영상으로 한다.

평면도·원본 지도에서 현재 라이다가 발견한 **지도상 빈 셀의 새 장애물**은 빨간
셀로, 실제 활성 국소 우회경로는 주황 점선으로 보인다. 현재 관측이 비거나 2초
넘게 갱신되지 않으면 빨간 셀이 사라진다. 지도·경로·로봇의 표시 기울기만
1.576° 보정하며 Nav2의 지도 좌표와 장애물 판정은 회전하지 않는다.

이 스크립트는 ROS 도메인 **76**과 로컬 Gazebo 포트 **11376**으로 격리된다. 실제 터틀봇 도메인 16에는 접근하지 않는다. 기본 시작 위치는 등록 Home `(-0.188431, -0.220497, -0.027514 rad)`이며 저장 지도와 AMCL 초기 위치가 같다. 종료는 실행한 터미널에서 `Ctrl+C`로 한다. 런치 옵션은 `run_sim.sh`와 동일하게 뒤에 붙일 수 있다.

기본값은 실차의 `curve_tuning_waffle_pi.yaml`과 `classroom_hardware_nodes.yaml`을 불러온다. Nav2 설정의 `use_sim_time`만 일시 파일에서 `true`로 바꾼다. 예전 이상적인 시뮬레이션 전용 튜닝과 비교할 때에는 `--ideal-profile`을 추가한다. 실제 로봇에서는 EKF가 Pi에서 돌지만 이 시뮬레이션 기본값은 기존 와플파이 오도메트리다. 독립 EKF/센서 지연을 동등하게 비교할 때에는 `localization_mode:=ekf_independent`, `ekf_params_file:=...`, `robot_model_file:=...` 인자를 별도로 지정해야 한다.

`ros2_ws/src/smart_vision_amr/scripts/generate_classroom_replay_world.py`는 `classroom_20261030_cleaned.pgm`의 검은 점 604개를 원래 지도 좌표의 **47개 직사각형 충돌 형상**으로 손실 없이 합친다. 지도에서 회색인 미탐색 영역을 임의의 벽으로 만들지 않는다. 중앙의 회색 내부와 검은 테두리는 실제 상자/구조물로 추정해 0.65 × 0.50 × 0.52 m 형상 하나를 추가했다. 이 추정 형상은 지도상 **미탐색 셀 안에만** 놓이며 자유 셀과 겹치지 않는다. 앞선 0.85 × 0.70 m 형상은 자유 셀 11개를 가려 빈 월드에서도 새 장애물로 잘못 잡혔다. 실물 치수를 측정하면 해당 생성기 상수와 지도를 함께 검토해야 한다. 세계 파일을 다시 생성하거나 일치 여부를 검사하는 방법은 다음과 같다.

```bash
/usr/bin/python3 ros2_ws/src/smart_vision_amr/scripts/generate_classroom_replay_world.py --check
/usr/bin/python3 ros2_ws/src/smart_vision_amr/scripts/generate_classroom_replay_world.py
```

더 가혹한 A/B 시험은 별도 `classroom_20261030_stress.world`를 쓴다. 기본 월드와 저장 지도는 그대로 유지하고, 지도상 자유 공간 `(0.35, -0.60)`에 지도에 없는 **20 cm × 20 cm 상자 하나**를 놓는다. 이 상자는 Sector 1→2의 기존 경로를 막지만 지도 5셀 정적 팽창과 차체·안전 여유를 포함한 동적 팽창에서도 대체 연결 경로가 남는다. 이전 후보 `(0.45, -1.00)`는 통로를 완전히 끊었고, `(0.20, -0.60)`는 실제 라이다 관측 셀의 팽창이 로봇 시작 셀을 막아 안전 정지했다. 과거 두 번째 상자 `(0.08, -1.75)`는 Sector 3 관찰 목표의 차체 안전 여유를 차지해 S3 진입을 막았으므로 제거했다. 현재 상자 하나의 월드에서 웹 소유 1→2→3→Home을 한 차례 완주했고, 라이다 관측→새 안전 경로→실측 우회를 확인했다. 별도로 Home 복귀 중 이동 장애물 주입 시험은 아직 전체 합격하지 못했다. 상자는 여전히 **저장 지도에 없는 장애물**이므로 라이다 관측과 국소 우회·재계획, 실제 차체 여유를 함께 검증한다. `libgazebo_ros_state.so`의 `/gazebo/link_states`에서 충돌 형상의 실제 위치를 확인한다.

```bash
./scripts/run_classroom_replay_sim.sh --stress gui:=false
```

지도는 평면 거리만 제공하므로 벽 높이 **0.70 m**, 중앙 물체 높이 **0.52 m**는 실제 측정값이 아니다. 로봇의 바퀴 마찰, 배터리 전압 하강, OpenCR 통신, 무선망 지연도 그대로 복제되지 않는다. 실차 장애물의 재질/반사 특성과 라이다 가림도 지도만으로 알 수 없다. 따라서 이 세계에서 합격해도 실차 합격을 보장하지 않으며, 재현 시험의 목적은 **지도 기하와 좁은 공간 때문에 생기는 경로·회피 실패를 먼저 드러내는 것**이다. 동적 장애물과 센서 지연은 별도 장애 주입 시험으로 확인해야 한다.

아루코 마커 0~3은 등록된 로봇 관찰 위치에서 후방 방향으로 광선을 쏴 처음 만나는 지도 벽의 자유 공간 쪽에 놓았다. 실제 마커를 붙인 벽의 정확한 좌표는 측정되지 않았으므로 **추정 배치**다. 검은 표식 한 변은 0·1번 **80 mm**, 2·3번 **100 mm**로 만들고 기존 4×4 사전 텍스처와 흰 여백 비율을 유지했다. 표식 중심 높이 **0.22 m**도 추정값이다. 기존 Gazebo 와플파이의 전방 카메라를 `/camera/front/image_raw`로 보내고, 후방 카메라를 `/camera/image_raw`에 추가한다. 후방 카메라 위치 `(-0.08, 0, 0.14 m)`와 수평 화각도 실차 장착 치수·캘리브레이션을 얻으면 갱신해야 한다.

2026-10-30 단독 Gazebo 기본 월드 검사에서 각 등록 관찰 자세로 로봇을 배치했을 때 후방 `640×480 rgb8` 영상을 OpenCV ArUco `DICT_4X4_50`으로 읽어 **0, 1, 2, 3번을 각각 검출**했다. 전방/후방 raw 및 compressed 토픽, 360개 빔의 `/scan`, `/odom`, `/gazebo/model_states` 발행도 확인했다. 이후 가혹 월드의 고정 상자 하나를 실제 라이다가 관측하고, 웹 소유 1→2→3→Home 임무에서 안전한 새 Sector 2 경로를 생성해 상자를 통과하고 전체 임무를 마친 것을 한 차례 검증했다. 2026-11-02 해당 실행은 `12_web_integrated_stress_clean` **PASS**이며, 차체 외접 반경 0.24m를 제외한 상자와의 Gazebo 실측 최소 여유는 0.1038m였다. 한 차례 시뮬레이션 합격은 반복 성공률이나 실차 성공을 보장하지 않는다.

초기 중앙 상자 치수를 쓴 기본 월드의 무장애 Home→Sector 3 단독 시험에서는 **68.7초에 목표 4.4 cm 이내 도착하고 정지**했지만 전역 계획 3회·국소 우회 시도 3회와 두 번의 경로 공백이 있었다. 벽 가까운 빈 셀 14개가 새 장애물로 관측됐고, 당시 중앙 상자 형상이 자유 셀을 침범해 지도와 불일치했다. 형상을 고친 최신 월드의 위 통합 시험과 이 초기 단독 시험은 서로 다른 버전의 증거이므로 합산하지 않는다. 초기 시험의 스캔·오도메트리·TF 전달 지연 95백분위는 각각 8/6/8 ms였다.

검증 순서는 ① 월드 파싱 및 카메라·라이다·오도메트리 토픽 확인, ② Home에서 Sector 3 또는 Home 복귀 경로 생성, ③ 기본/가혹 세계에서 정지·국소 우회·전체 재계획의 차이를 관찰, ④ 이동 장애물과 센서/TF 지연을 추가해 출발 대기와 복구 동작을 확인하는 것이다. 실차와 비교할 때에는 `/scan`, `/odom`, `/amcl_pose`, `/smart_vision_amr/observed_obstacles`, `/smart_vision_amr/navigation_status`, 재계획 로그의 시각과 값을 함께 기록한다.
