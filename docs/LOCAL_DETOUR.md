# 국소 우회와 원래 경로 합류

작은 장애물이 갑자기 나타났을 때 목적지까지의 전체 경로를 먼저 지우지 않고,
장애물 주변의 짧은 구간만 돌아서 원래 경로의 **앞쪽**에 합류합니다.
실차와 Gazebo 모두 기본으로 켜며, 실행은 [세 터미널 매뉴얼](TEAM_QUICKSTART.md)과 같습니다.

## 처리 순서

1. 라이다로 새 장애물을 관측하고 남은 주행 경로와 겹치는지 확인합니다.
2. 가까운 장애물이면 원래 경로 앞쪽의 안전한 합류점을 고릅니다.
3. 제한된 범위에서 짧은 우회 경로를 계산하고, 합류점 뒤의 원래 경로는 유지합니다.
4. Nav2가 우회 경로를 추종하며 라이다 비용지도로 이동·회전 후보를 계속 확인합니다.
5. 위치와 독립 odom으로 합류 진행이 확인되면 원래 경로를 이어갑니다.

우회 경로도 격자 A*로 계산하지만, 검색 범위와 합류점을 제한합니다.
목적지나 방문 순서를 바꾸거나, 목표 쪽의 열린 방향으로 임의 주행하는 방식은 아닙니다.

국소 우회가 불가능하거나 진행하지 못하면 기존 복구 절차를 사용합니다.

`전체 A* 재계획 → 필요 시 확인된 직전 경로로 짧게 후진 → 새 위치에서 재계획`

후진은 최신 센서·주행 기록·차체 여유가 확인되는 경우에만 가능합니다.
통로가 완전히 막혀 전진·후진 모두 불가능하면 목표를 유지하고 장애물 해소를 기다립니다.

## 충돌 확인

라이다 거리값은 주행 중 계속 갱신되는 피드백입니다. 차체 반지름과 안전 마진은 설정값입니다.
정적 지도·미확인 영역·실시간 장애물·장애물 기억과 차체가 겹치지 않는 경로만 허용합니다.
모서리를 대각선으로 가로지르는 경로나, 차체 여유가 없는 합류점은 사용할 수 없습니다.
기존 장애물 팽창을 줄여 통과시키지 않습니다.

처음에는 물체의 정면만 보이고 옆면·뒷면은 가려질 수 있습니다. 정면 바로 뒤를
안전한 합류점으로 고르지 않도록, 경로를 막는 측정점 뒤에 진행 방향으로 기본 0.5m의
임시 여유 구역을 둡니다. 마지막 차단 구간을 지난 뒤에도 0.15m를 더 진행한 합류점을 고릅니다.
이는 국소 경로 계산에만 쓰는 보수적인 여유이며 실제 관측값·저장 지도·장애물 기억을
만들어 넣는 기능이 아닙니다. 물체가 이 범위보다 크거나 새 장애물이 나타나면 최신 라이다로
다시 검사하고 기존 전체 계획·복구로 전환합니다. 우회 경로는 갱신된 장애물과의 거리 비용도
사용해 팽창 영역의 가장자리에 지나치게 붙지 않도록 합니다.
격자 한 칸의 관측 흔들림으로 우회 경로가 즉시 취소되지 않도록, 국소 계산의 동적
장애물에 기본 0.05m의 관측 여유도 더합니다. 실제 충돌 검사나 전체 계획의 팽창을
줄이는 기능이 아니며, 더 큰 새 장애물이 우회를 막으면 기존처럼 전체 계획으로 전환합니다.

수동 조종·비상정지·센서 지연·위치 신뢰도 저하가 있으면 기존 정지·제어권 정책이 우선합니다.
새 경로 전달 때도 Nav2의 이전 동작 취소 완료를 확인한 뒤 다음 경로를 보냅니다.

## 조절값

실차 설정은 `ros2_ws/src/smart_vision_amr/config/classroom_hardware_nodes.yaml`의
`/astar_planner/ros__parameters`에 있습니다. 시뮬레이션 설정에도 같은 항목을 두었습니다.

| 파라미터 | 기본값 | 의미 |
|---|---:|---|
| `local_detour_enabled` | `true` | 국소 우회 사용 |
| `local_detour_trigger_distance` | 1.5m | 남은 경로를 막는 장애물을 가까운 것으로 판단할 차량 주변 거리 |
| `local_detour_max_rejoin_distance` | 2.5m | 원래 경로를 따라 합류점을 찾을 전방 거리 |
| `local_detour_max_length` | 4.0m | 허용할 우회 구간 최대 길이 |
| `local_detour_max_lateral_distance` | 0.9m | 원래 경로에서 벗어날 수 있는 옆 방향 범위 |
| `local_detour_clearance_margin` | 0.02m | 차체 반지름에 더할 여유. 기존 팽창보다 작아지지 않음 |
| `local_detour_observation_margin` | 0.05m | 국소 동적 장애물의 격자·관측 흔들림에 대비할 추가 여유 |
| `local_detour_occlusion_extension` | 0.5m | 경로를 막는 측정점 뒤에 임시로 확보할 미관측 물체 깊이 |
| `local_detour_rejoin_buffer` | 0.15m | 마지막 차단 구간을 지난 뒤 합류까지 더 둘 거리 |
| `local_detour_max_expansions` | 1500 | 한 번의 국소 검색에서 확장할 최대 셀 수 |
| `local_detour_max_planning_time` | 0.06초 | 국소 검색 시간 제한 |
| `local_detour_max_candidates` | 10 | 검토할 최대 전방 합류점 수 |
| `local_detour_max_attempts` | 3 | 합류 확인 전 반복 우회 제한 |

설정 파일을 열려면 PC에서:

```bash
cd ~/Team2_workspace/src/SMART-VISION-AMR
code ros2_ws/src/smart_vision_amr/config/classroom_hardware_nodes.yaml
```

기존 방식과 비교할 때는 **주행을 정지한 뒤** 해당 파일의
`local_detour_enabled: false`로 저장하고 주행 터미널을 다시 실행합니다.

## 지연을 해석하는 방법

국소 검색의 0.06초 제한은 라이다 수신부터 차량이 움직일 때까지의 총시간이 아닙니다.
라이다·TF 수신, 경로 검사, Nav2 취소 확인과 새 경로 수락 시간이 별도로 있습니다.
기존 전체 재계획의 재시도 간격 2초와 진행 정체 판정 6초도 항상 합산되는 시간은 아닙니다.

계획 상태에서 국소 검색·전체 계획 시간을 구분해 확인하고, 실제 시험에서는
장애물 관측 → 우회 경로 발행 → 차량 재출발 시간을 각각 측정합니다.
검색 제한에 걸리면 범위를 무제한 늘리지 않고 전체 계획·기존 복구로 전환합니다.
초기 0.04초 설정은 CPU 경합 시험에서 제한에 걸린 사례가 있어, 계산 중복을 줄인 뒤
운용 기본값에 0.02초의 여유를 더했습니다. 충돌·확장 셀 수·재시도 한도는 유지합니다.
시간 제한이 0 또는 0.1초 초과이거나, 여유가 음수인 등 잘못된 국소 우회 설정은
`invalid_configuration`으로 표시하고 기존 전체 계획을 사용합니다.

현재 계획 종류와 계산 시간을 확인하려면 PC의 별도 터미널에서:

```bash
source /opt/ros/humble/setup.bash
source ~/Team2_workspace/install/local_setup.bash
export ROS_DOMAIN_ID=16 ROS_LOCALHOST_ONLY=0
ros2 topic echo /smart_vision_amr/planner_status
```

`plan_kind: LOCAL_DETOUR`는 국소 우회, `GLOBAL`은 전체 계획입니다.
`local_detour_state`의 `ACTIVE`는 우회·합류 중, `REJOINED`는 실제 합류 확인입니다.
`search_duration_ms`는 국소 검색, `adapter_duration_ms`는 준비를 포함한 국소 처리,
`global_duration_ms`는 전체 계획 처리 시간입니다. 출력은 `Ctrl+C`로 끝냅니다.

Gazebo의 갑작스러운 장애물·통로 차단 시험 결과는
[검증 기록](../benchmarks/startup_20261030/README.md)에 정리합니다.
