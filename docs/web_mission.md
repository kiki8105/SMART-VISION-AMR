# 웹 ArUco 경유 임무

웹 화면에서 방문할 마커 ID를 추가하고 순서를 바꾼 뒤 임무를 시작합니다.
기본 예제는 `2 → 3`이며, `0 → 2 → 3`, `3 → 2`, `2 → 2 → 3`처럼
등록된 ID를 사용해 순서를 변경하거나 같은 ID를 반복할 수 있습니다.
브라우저는 PC에서 실행 중인 ROS 연결 서버와 통신하므로 휴대전화에 ROS를
설치할 필요가 없습니다.

재고 관리자 요청과 운용자 적재·배송 흐름은 [재고 배송 안내](inventory_delivery.md)를
참고하세요. 기존 수동 마커 편집은 운용자 화면의 **수동 마커 임무 · 실습용**에 있습니다.

## 실패 접근 기억과 복구 표시

주행 중 같은 코너의 진입 실패가 반복되면 현재 단계 아래에 **실패 접근 회피** 상태가
표시됩니다. 계획 노드의 `/smart_vision_amr/failure_memory_status`를 받아
`재계획 → 대체 경로 대기 → 안전 후진 → 새 경로 진입 확인`을 구분합니다.
**실패 접근 기억 보기**를 펼치면 실패 위치, 원인과 임시 제한의 남은 시간을 볼 수 있습니다.
남은 시간은 재평가 시점이며 성공이나 자동 출발을 보장하는 카운트다운이 아닙니다.

이 정보는 저장된 SLAM 지도를 수정하지 않는 계획용 임시 메모리입니다.
센서 단절은 **센서 회복 대기**로 표시하며 새로운 경로 실패로 기록하지 않습니다.
조이스틱·일시정지·비상정지가 복구보다 우선합니다. 웹 화면은 상태를 표시할 뿐
실패 기억을 삭제하거나 후진을 직접 시작하지 않습니다.

이전 목표의 상태가 새 임무에 섞이지 않도록 현재 목표의 정확한 시각 식별자를 대조합니다.
2초 이상 갱신되지 않은 상태와 종료된 임무의 복구 표시는 숨깁니다.

장애물로 경로가 막혀 정해진 재시도를 마치면 **장애물 해소 대기**와 함께
“장애물이 있어 경로 주행을 잠시 멈춥니다. 장애물을 치우면 경로를 재개합니다.”를
표시합니다. 현재 목표와 재시도 횟수는 유지하며 장애물 해소를 기다립니다.
센서 수신이 끊기면 장애물 제거 안내 대신 **센서 회복 대기**를 표시합니다.
수동 조종·일시정지·비상정지 중에는 이 안내가 자동 재개 권한을 만들지 않습니다.

## 처음 한 번 빌드

새 실행 노드가 추가되었으므로 Team2 워크스페이스에서 한 번 빌드합니다.
이후 실행 스크립트는 빌드를 반복하지 않습니다.

```bash
sudo apt install python3-opencv python3-numpy python3-pil python3-yaml
cd ~/Team2_workspace
source /opt/ros/humble/setup.bash
colcon build --packages-select smart_vision_amr --symlink-install
source install/local_setup.bash
```

저장소를 다른 경로에 두었다면 해당 워크스페이스 경로를 사용합니다.
스크립트는 자신의 저장소 위치에서 기본 워크스페이스를 찾습니다.
다른 빌드 위치는 `--workspace /절대경로` 또는
`SMART_VISION_WEB_WORKSPACE=/절대경로`로 지정할 수 있습니다.

## 터미널 1: 미로 시뮬레이션과 지도 주행

```bash
~/Team2_workspace/src/SMART-VISION-AMR/scripts/run_web_mission_sim.sh
```

마커 4개가 있는 미로 월드, 저장된 실측 지도, AMCL, 팀 A*, Nav2 경로 추종을
함께 시작합니다. Gazebo 창은 켜고 RViz는 켜지 않습니다. Gazebo 화면이
필요 없으면 명령 뒤에 `gui:=false`를 붙입니다. 새 SLAM을 수행하지 않고
저장소에 포함된 `ros2_ws/src/smart_vision_amr/maps/maze_aruco_20261026.yaml`과
`.pgm`을 사용합니다. 마커 0~3의 모델·재질·이미지도 `gazebo_models/`에 포함되어
있으므로 지도 복사나 모델 등록을 따로 하지 않습니다.

웹 조이스틱은 motion mux를 통해 수동 조작을 우선합니다. 제공 시뮬레이션의
기본 `use_motion_mux:=true`를 유지하고, `/cmd_vel`을 직접 발행하는 PyQt 방향
버튼이나 별도 키보드 조종기를 같은 시뮬레이션에 동시에 연결하지 않습니다.

기본 통신은 `ROS_DOMAIN_ID=76`, `ROS_LOCALHOST_ONLY=1`, Gazebo 포트 `11376`입니다.
기존 셸의 실차 도메인을 이어받아 연결하지 않습니다. 별도 도메인에서
실습하려면 두 스크립트에 같은 번호를 지정합니다. 예를 들어 다음 명령은
도메인 82, Gazebo 포트 11382에서 실행합니다.

```bash
SMART_VISION_WEB_DOMAIN_ID=82 ~/Team2_workspace/src/SMART-VISION-AMR/scripts/run_web_mission_sim.sh gui:=false
```

## 터미널 2: 웹 화면과 ROS 연결

```bash
~/Team2_workspace/src/SMART-VISION-AMR/scripts/run_web_mission.sh
```

PC에서 `http://localhost:8790`을 열면 바로 연결됩니다. 휴대전화는 PC와 같은 Wi-Fi에 연결하고
`http://PC의_IP:8790`을 엽니다. PC 주소는 `hostname -I` 출력 중 휴대전화와
같은 네트워크의 IPv4 주소를 사용합니다. HTTP 서버는 기본적으로 PC의
네트워크 인터페이스에서 연결을 받으며, 페어링 코드는 서버를 시작할 때
표시됩니다. 휴대전화에는 이 코드를 입력하세요. PC 웹 화면의 **차량 연결**
창에서도 주소와 코드를 볼 수 있습니다. PC에서만 사용하려면 `--host 127.0.0.1`을 지정합니다.

도메인 82로 실행한 시뮬레이션에는 다음과 같이 연결합니다.

```bash
~/Team2_workspace/src/SMART-VISION-AMR/scripts/run_web_mission.sh --domain-id 82
```

다른 HTTP 포트는 `--port 8792`로 지정합니다. 웹 포트와 ROS 도메인은 서로
다른 설정입니다. 휴대전화가 접속하는 주소에는 변경한 HTTP 포트를 넣습니다.

## 임무 편집과 주행

1. 지도와 카메라 영상, 로봇 위치가 들어오는지 확인합니다.
2. 마커를 추가하고 위·아래 이동 또는 삭제로 경유 순서를 정합니다.
3. 순서를 저장하고 **시작**합니다.
4. 로봇이 각 마커의 관측 위치와 방향에 도착한 후, 실제 카메라 영상에서
   해당 ID가 연속 확인되어야 다음 경유지로 이동합니다.
5. 마지막 마커까지 확인하면 저장된 Homepoint로 자동 복귀해 대기합니다.

마커가 화면에 잠깐 보이는 것만으로 경유 완료가 되지 않습니다. 도착 후의
새 영상, 해당 관측 위치와 방향, 정지 상태를 함께 확인합니다. ID가 보이지
않으면 카메라 화면에서 마커의 앞면과 가림 여부를 확인합니다.

주행 중 순서를 편집하고 저장하면 **다음 시작에 사용할 순서**로 보관합니다.
현재 진행 중인 임무의 순서는 바뀌지 않습니다. 새 순서를 즉시 사용하려면
**일시정지 → 새 순서로 시작**합니다. 이때 이전 주행의 취소 응답을 확인한 뒤
새 경로를 전달하며, 기존 홈 위치는 유지합니다. 일시정지 후 새 순서를
저장하지 않고 **재개**하면 기존 순서를 이어서 진행합니다.

## 홈 복귀와 임무 취소

Homepoint는 도메인별로 저장된 고정 대기 위치와 방향입니다.
기본값은 등록된 마커 0번의 로봇 관측 위치이며, 정지 상태에서
**현재 위치를 Homepoint로 설정**해 변경할 수 있습니다. 새 임무 시작이나
추가 요청으로 덮어쓰지 않으며 서버를 다시 시작해도 유지합니다.

- **홈 복귀**: 현재 경유 임무를 종료하고 저장된 홈으로 이동합니다.
- **임무 취소 · 복귀**: 남은 경유 임무를 취소하고 홈으로 이동합니다.
- **일시정지**: 현재 위치에서 정지합니다. 홈으로 이동하지 않습니다.
- **비상정지**: 정지를 유지합니다. 홈 복귀도 실행하지 않습니다.

복귀할 때는 기존 주행의 취소가 확인될 때까지 정지하고, A*가 생성한
복귀 경로를 따라 이동합니다. 경로가 막히면 목표를 유지한 채 재계획을
기다립니다. 홈 도착은 해당 복귀 명령의 완료 응답, 실제 위치와 방향,
정지 상태로 확인하며 ArUco 마커나 카메라 확인을 요구하지 않습니다.
복귀 중에도 일시정지·재개와 비상정지를 사용할 수 있습니다.
홈 복귀 중 저장한 새 경유 순서는 복귀 완료 후 새 임무 시작에 적용됩니다.
이때 **홈 복귀 재개**는 새 경유지 대신 원래 홈으로 이동합니다.

홈이 아직 기록되지 않았거나 비상정지 중이면 복귀를 시작할 수 없습니다.
복귀에도 최신 TF·LiDAR·오도메트리와 지도·주행 노드가 필요합니다.

**비상정지**는 해제 전까지 유지됩니다. 해제해도 자동으로 출발하지 않으며,
다시 시작 명령을 내려야 합니다. 외부 조종기에서 중지한 경우에도 웹에서
명시적으로 재개해야 합니다.

## 경로가 막혔을 때

A*가 일시적으로 경로를 찾지 못해도 목적지는 유지합니다. 로봇은 정지하고
재계획을 기다리며, 경로가 다시 확보되면 같은 목표로 이어서 이동합니다.
실패한 경로의 중복 기록은 초기화하여 동일한 유효 경로도 다시 전송할 수
있습니다. 사용자가 누른 일시정지·비상정지는 자동 재계획으로 해제하지
않습니다. 임무 취소 뒤에는 경유 목표 대신 홈 목표로 재계획합니다.
장애물 팽창을 없애거나 점유된 셀을 통과시키는 방식은 사용하지
않습니다.

## 마커 좌표 수정과 실차 연결

관측 위치는 다음 파일에 등록되어 있습니다.

```text
ros2_ws/src/smart_vision_amr/config/aruco_mission_markers.yaml
```

`x`, `y`는 현재 사용하는 **map 좌표계에서 로봇이 멈출 위치**입니다. 기본 미로
시뮬레이션의 `yaw`는 전방 카메라가 마커를 바라보는 방향입니다. 실차 강의실
프로필에서는 `yaw`가 **차체 전방(`base_footprint`) 방향**이며 후방 카메라는
그 반대 방향(`yaw + π`, 180°)을 봅니다. 따라서 실차용 마커의 `yaw`를
카메라 방향으로 다시 뒤집어 입력하지 마세요. 벽에 붙은 마커 중심 좌표를 목표로
사용하지 않습니다. 파일을 수정한 뒤 서버를 다시 시작하면 읽어옵니다.
다른 파일은 `--markers-file /절대경로/markers.yaml`로 선택합니다.

실차에서는 로봇 bringup과 해당 실차 지도의 위치 추정·주행 노드가 먼저
실행되어야 합니다. 웹 서버를 실행하는 PC에서 예를 들어 다음과 같이
연결합니다. 다음 명령은 시뮬레이션을 실행하지 않습니다.

```bash
~/Team2_workspace/src/SMART-VISION-AMR/scripts/run_web_mission.sh \
  --domain-id 16 --no-use-sim-time \
  --markers-file /절대경로/실차_지도에_등록한_마커.yaml
```

기본 마커 좌표는 미로 시뮬레이션 지도의 좌표입니다. 실차에서는 새로 만든
실차 지도에 각 마커의 관측 위치와 **차체 전방 yaw**를 등록한 YAML을 사용합니다.
지도 화살표도 차체 전방을 가리키며, 마커는 실차의 후방 카메라에 보여야 합니다.
실차 기본 EKF 브링업의 후방 카메라 토픽은 `/camera/image_raw/compressed`다.
전방 카메라를 활성화하면 `/camera/front/image_raw/compressed`로 별도 표시한다.
원본 `v4l2` 백엔드를 선택한 경우에는 각 토픽의 `/compressed` 접미사를 뺀
원본 영상도 발행한다. 웹 서버의 `--camera-topic`은 후방,
`--front-camera-topic`은 전방 영상 토픽을 지정한다. 전방 영상이 없으면 전방
칸에 수신 대기가 표시되며, 후방 영상과 LiDAR 기반 위치 확인은 계속 사용할 수 있다.
실차용 `scripts/robot_bringup_camera_16.sh`는 매 실행마다 이름이 `camera0`인
전방 V4L2 장치를 찾고, `v4l2-ctl`에서 YUYV 640×480 또는 320×240 형식이
확인되면 전방 드라이버를 추가한다. 장치나 지원 형식이 없으면 전방을 건너뛰고
후방 브링업을 유지한다. 실차의 `camera0`은 단계식 크기의 YUYV를 지원하지만,
변경된 스크립트의 실제 영상 수신은 로봇을 다시 켠 뒤 확인해야 한다.

후방 웹캠을 로봇에 연결했다면
브링업 스크립트의 기본 `CAMERA_DEVICE`는 실차 후방 웹캠의
`/dev/v4l/by-id/usb-BY-5640-200408_Webcam_01.00.00-video-index0`입니다.
웹캠을 교체했다면 이 경로를 다시 확인하고 실행 시 `CAMERA_DEVICE`로 지정합니다.
`--no-use-sim-time`은 실제 시간을 사용하고, ROS 네트워크 검색을 활성화합니다.
`SMART_VISION_WEB_LOCALHOST_ONLY=0` 또는 `1`로 ROS 검색 범위를 따로 지정할
수 있습니다. HTTP 접속 범위는 `--host`가 담당합니다.

서버와 시뮬레이터는 각각 실행한 터미널에서 `Ctrl+C`로 종료합니다.

## 설정과 검증

마커 순서는 Domain별로 `~/.config/smart-vision-amr/web-mission.json`에
영구 저장됩니다. HTTP 포트는 시작 스크립트에서 지정하고, 차량 Domain과
시뮬레이션 시계는 웹의 차량 연결 창에서도 바꿀 수 있습니다. 연결 변경은
진행 중인 임무가 없고 기존 주행의 취소가 확인된 상태에서만 가능합니다.
