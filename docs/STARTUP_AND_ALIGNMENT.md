## 초기 위치 확인

AMCL의 위치 표준편차는 로봇이 생각하는 위치의 불확실도입니다. 등록 Home과
평균 위치가 가깝더라도 불확실도가 크면 초기 위치 검증을 통과하지 못합니다.
기존 위치 경고 기준인 **0.35m**는 유지했습니다.

전원을 켤 때 실제 로봇은 등록 Home에서 후방 카메라가 0번 표식을 바라보도록 놓습니다.
홈 기준 **자세 초기화**는 등록 좌표·방향을 AMCL 초기 가설로 입력하는 단계까지 포함합니다.
좌표를 RViz에서 따로 지정할 필요가 없습니다. 저속 회전으로 위치를 확인한 뒤 등록 Home의
방향으로 다시 정렬하고 정지하며, 초기화 완료 때문에 배송의 홈 방향 조건이 막히지 않게 합니다.
실제 홈이 아닌 곳에서는 이 기능으로 홈 좌표를 강제 입력하지 않고 일반 위치 확인을 사용합니다.
0번 표식이 검출되면 홈 확인의 보조 근거로 사용합니다. 표식만으로 위치를 계산하거나,
검출되지 않았다는 이유만으로 홈 가설 입력을 막지는 않습니다. 실제 홈 위치·방향의 확인과
최신 LiDAR·저장 지도 일치는 필요합니다.
저속 회전·홈 방향 복귀·정지 후 새 측정 확인에는 시간이 필요합니다. 화면에서 현재 단계를
확인하며 기다리세요. 회전과 복귀는 같은 최대 65초·누적 측정 회전 360° 한도 안에서 수행하고,
제한을 넘으면 성공 처리하지 않고 정지합니다.

- 정지한 채 위치 검증을 기다릴 때도 신선한 라이다·odom·TF가 있으면 AMCL에
  실제 라이다 필터 갱신을 요청합니다. 기본 2초 간격, 최대 10회·30초로 제한합니다.
- 요청 성공만으로 위치나 신뢰도를 정상으로 표시하지 않습니다. 실제 새 AMCL 결과가 필요합니다.
- 라이다보다 TF가 조금 늦게 오는 경우 측정 시각에 맞는 TF를 최대 0.2초 기다립니다.
  최신 라이다가 계속 TF를 앞서더라도, 아직 신선한 직전 측정의 정확한 TF를 사용할 수 있습니다.
  센서 시각을 현재 시각으로 바꾸거나 오래된 입력을 신선하게 처리하지 않습니다.
- 위치 확인 회전은 주행 취소 → 새 정지 명령 수락 → 실제 정지 확인 → 회전 전용
  제어권 확보 순서입니다. 조이스틱과 비상정지가 우선합니다.
- 위치 감시 노드의 동적 `/tf` 구독은 기본 BEST_EFFORT로 설정합니다. Gazebo 시험에서
  원본 TF는 계속 수신되는데 기존 RELIABLE 구독의 버퍼만 뒤처진 사례를 확인했습니다.
  `/tf_static`은 RELIABLE·TRANSIENT_LOCAL을 유지하며, TF의 원래 시각과 안전 검사도 유지합니다.
  이 변경이 실차 통신 문제 전체의 원인을 확정한 것은 아닙니다.
- Nav2의 동적 TF 구독도 BEST_EFFORT·깊이 20으로 설정하며 정적 TF는 유지합니다.
  AMCL 내부의 별도 TF 구독에도 적용됩니다. `nav2_dynamic_tf_best_effort:=false`로
  실행하면 이 덮어쓰기를 생략하고 설치된 Nav2의 기본값을 사용합니다.
- 유효한 시각이 있는 차체 외곽은 같은 측정 시각의 실제 odom·TF와 비교합니다.
  시각이 오래된 외곽의 예외 처리는 수신 당시 위치 증명과 기존 현재 위치 10cm 한도를
  함께 요구합니다. 서로 다른 시각의 값을 곧바로 비교하는 오류를 줄이며,
  위치를 예측하거나 안전 여유를 느슨하게 하지 않습니다.
- 회전 중 일시적인 위치 감시·TF 지연은 즉시 0 속도로 멈추고 최대 1초 동안 복구를
  기다립니다. 새 입력과 회전 제어권이 다시 확인돼야 같은 위치 확인을 이어갑니다.
  비상정지·위험 상태 또는 지속적인 수신 중단이면 중단합니다.
- 완료하려면 회전 후 정지와 새 AMCL 결과, 정상 위치 신뢰도를 확인해야 합니다.
  초기화 완료나 비상정지 해제만으로 임무를 출발시키지 않습니다.

웹은 센서 대기, 위치 불확실도, 제어권 응답 대기, 비상정지를 구분해 다음 행동을 표시합니다.
PC와 로봇 시계가 다르거나 센서가 끊긴 문제는 위치 초기화만으로 해결되지 않습니다.
[배포 점검](DEPLOYMENT_CHECK.md)으로 입력 시각과 발행자를 먼저 확인하세요.

### 출발하지 않을 때 확인 순서

웹의 **출발 준비 초기화**를 열면 실제 정지·센서·위치·제어권 단계를 확인할 수 있습니다.
이는 안전 검사를 건너뛰는 전체 리셋이 아닙니다. 단계별 기존 동작을 사용하며,
홈 위치 지정·홈 기준 자세 초기화에는 사용자의 실제 홈 확인이 필요합니다.
비상정지 해제는 별도 확인으로 수행하고, 위치 확인 완료 후에도 임무를 자동 출발시키지 않습니다.

| 표시·상태 | 확인할 내용 |
|---|---|
| scan/odom 수신 대기 | 로봇 브링업, 도메인 16, 발행자 중복과 두 장치의 시각 확인 |
| 초기 위치 검증·위치 불확실도 | 실제 홈 여부 확인 후 홈 초기 위치 지정, 새 AMCL 결과와 센서 안정화 대기 |
| 정지 응답·회전 제어권 대기 | PC와 로봇이 같은 버전인지 확인, 다른 운용자의 조이스틱·중복 웹/주행 중지 |
| 지도 TF 대기 | 저장 지도와 AMCL 활성화, 실제 초기 위치, PC/로봇 시계 차이 확인 |
| Nav2 입력 오류 | `/smart_vision_amr/navigation_status`의 구체적인 센서·costmap·footprint 사유 확인 |

목표 요청 거부, 경로 생성 실패, Nav2 수락 실패, 최종 속도 차단은 서로 다른 단계입니다.
경로 계산이 빠르더라도 앞 단계의 위치·제어권 검사를 통과하지 못하면 출발하지 않습니다.
먼저 차단된 단계를 확인하고, 기준값을 키우거나 정지를 강제 해제해 문제를 숨기지 않습니다.

## 섹터 도착 판정

실차 기본 설정은 Sector 1~3의 관측점에 도착한 뒤 후방 카메라가 해당 번호의
아루코를 **연속 영상에서 확인하면** 승인합니다. 표식을 발견한 뒤에는 화면의
한가운데나 벽과 정확히 직각이 되도록 더 회전하지 않습니다. 목표 x/y와
접근 yaw는 경로 계획의 기준으로 유지합니다.

| 위치 | 차체 전방 yaw | 도착 확인 |
|---|---:|---|
| Home | 0° | 지도상 위치·방향과 실제 정지 |
| Sector 1 | 180° | 후방 1번 표식·실제 정지 |
| Sector 2 | 90° | 후방 2번 표식·실제 정지 |
| Sector 3 | -90° | 후방 3번 표식·실제 정지 |

섹터 경로 도착 뒤 표식이 보이지 않으면 제한된 범위에서 저속 회전하며 찾습니다.
올바른 ID의 도형 품질이 유효한 새 영상 3개 이상과 0.6초 이상의 정지 상태가
확인되어야 합니다. 지도상 목표 근처의 최신 위치·라이다·오도메트리와 위치
신뢰도 검사도 유지합니다. 다른 ID, 오래된 영상, 움직이는 로봇, 회전 여유가
없는 장소는 승인하지 않습니다. 탐색 시간·회전 한도를 넘으면 목표를 유지한 채
일시정지합니다.

이 기본 설정은 **차체와 벽의 90° 정렬을 보증하지 않습니다.** 2026-10-30 실차
Sector 3 재시험에서 표식은 자동 검출됐지만 가로 중앙과 라이다 벽 직각 방향이
서로 반대 회전을 요구해 45초 뒤 정지했습니다. 같은 자리에서 회전만으로
두 조건을 동시에 맞출 수 없어, 이번 임무에서는 반복 검출을 도착 기준으로
사용합니다. 정밀 도킹이 필요하면 관측 위치의 가로 보정과 카메라 장착 각도
실측을 별도 단계로 구현해야 합니다.

카메라 장착 위치와 후방 영상의 180° 회전은 별개입니다.
[카메라 실측 위치 전달 방법](DEPLOYMENT_CHECK.md#섹터-표식과-벽-방향)을 참고하세요.
