## 1. 개요

본 보고서는 기존 시스템에서 발생한 출발 지연, 불필요한 선회, 반복 정지 및 복귀 정체를 검토하고, 현재 시스템에 적용한 개선 내용과 확인된 성능 차이를 정리한다.

결과 판정의 출발점은 **11월 4일 실차 FTA**다. FTA의 사건 ID를 개선 조치·검증 근거·종결 상태에 연결하며, 개선된 수치에 맞춰 과거 원인을 소급해서 바꾸지 않는다. 11월 5일 추가로 발견한 계산·명령 처리 문제는 별도 개선 항목으로 구분한다.

이번 개선은 A* 알고리즘을 다른 알고리즘으로 교체한 작업이 아니다. 기존 A*·Nav2·EKF·AMCL·장애물 기억·웹 임무 체계를 유지하면서 **경로 추종과 복구 동작을 정리하고, 검사 계산이 명령 수신을 지연시키는 실행 구조를 개선한 작업**이다.

수정 후 사용자는 실차 주행에 대해 **“잘된다”**고 확인했다. 이는 현재 시험에서 주행 동작이 개선됐다는 관찰 결과로 기록한다. 별도 기록이 없는 반복 왕복 성공률, 장애물 우회 성공률 또는 위치 정확도 향상까지 의미하지는 않는다.

### 1.1 비교 기준

기능 구성과 승인·고장 논리의 시각 자료는 [기존·현재 시스템 블록 및 논리 비교도](SYSTEM_BLOCK_LOGIC_COMPARISON_20261105.md)에 정리했다.

| 구분 | 기준과 해석 |
|---|---|
| 기존 시스템 구성 | 11월 4일 마지막 저장소 커밋 **ad9aa3a**와 당일 실차 분석 문서 |
| 변경 시스템 구성 | **7286c41** 기반 소스에 11월 5일 실차 끊김 개선을 추가한 현재 작업본 |
| 어제와 오늘의 실차 비교 | 당시 로그와 현재 사용자 관찰을 이용한 정성 비교 |
| 계산 시간 비교 | **11월 5일 당일** 로봇의 합성 입력 시험에서 수집한 최적화 전후 수치 |

11월 4일에는 설정이 여러 차례 변경됐다. 따라서 당시 모든 실차 시험이 마지막 커밋과 동일한 설정으로 실행됐다고 간주하지 않는다. 아래 설정 표는 비교 가능한 **저장소 스냅샷**을 기준으로 한다.

## 2. 기존 시스템 구성

### 2.1 기능 구성

| 계층 | 기존 구성과 역할 |
|---|---|
| 센서·구동 | 라이다, 바퀴 엔코더, IMU, 후방 카메라, OpenCR 및 모터 |
| 연속 위치 추정 | 바퀴 측정값과 IMU를 사용하는 독립 EKF, odom 및 관련 TF 생성 |
| 지도상 위치 추정 | 저장 지도와 라이다를 대조하는 AMCL, map→odom→base 연결 |
| 경로 생성 | 저장 지도·관측 장애물·기억 정보를 반영하는 A* |
| 경로 추종 | path_follower가 Nav2 FollowPath를 사용해 주행 |
| 복구 | 국소 우회, 제한된 후진, 재계획 및 실패 경로 기억 |
| 최종 명령 제어 | motion_mux의 수동 우선 중재, 비상정지, 센서·위치 상태 검사 |
| 임무·관제 | 재고 요청, 섹터 순차 이동, 후방 ArUco 확인, 대기 및 Home 복귀 |

국소 우회, 후진, 장애물 기억, 수동 조종 우선권과 다중 스레드 실행기는 기존에도 존재했다. 이를 이번 작업에서 처음 도입한 기능으로 분류하지 않는다.

기능의 존재와 실행 시 활성화 여부는 다르다. 11월 4일 현장 데모 문서에는 기억 기능이 꺼진 실행 설정이 기록돼 있다. 현재 실행은 기억 기능을 켜지만 디스크 저장·복원은 끄는 **주행 세션 내 기억**을 사용한다.

11월 4일 현장 데모 문서에는 브링업·카메라·주행·웹을 로봇에서 실행하는 구성이 기록돼 있다. 저장소에는 PC와 로봇을 분리하는 구성도 이미 있었으므로, 실행 배치와 기능의 신규 도입 여부는 구분한다.

## 3. 기존 시스템 성능 및 문제점

### 3.1 11월 4일 실차 기록

| 항목 | 확인된 사실 | 평가 |
|---|---|---|
| 기본 배송 | Sector 2 배송 2건과 Home 복귀 기록 2회 존재 | 기본 임무 수행 가능성 확인 |
| 복귀 연속성 | 일부 복귀에서 선회 공간 문제로 수동 위치 조정 후 재개 | 독립적인 연속 운용에는 보완 필요 |
| 경로 생성 실패 | 분석 대상 기록에서 A* 경로 없음 17회. 이 중 시작점 정적 차단 8회 | 출발 위치와 지도 셀 처리 검토 필요 |
| 장애물 기억 영향 | 위 17회 모두 기억 장애물 수는 0 | 해당 실패를 기억 기능 탓으로 판단할 근거 없음 |
| 시각 정합 | footprint 시각이 odom 이력보다 약 49~100ms 앞선 경고 5회 | 취소가 함께 기록됨. 전체 정체에 미친 영향 정도는 미확정 |
| 마지막 Home 접근 | 별도 사례에서 거리 약 0.16~0.17m, 방향 오차 약 135°, 속도 명령 약 0.01m/s 이하 | 목표 근처 회전·진행 판정 보완 필요 |
| 최종 위치 정합 | 복귀 완료 약 149초 뒤 스냅샷의 추정 자세가 당시 활성 사용자 지정 Home과 약 0.82m·151° 차이. 그때 위치 신뢰도는 불량 | 완료 순간의 실측이 아니므로 오도착 확정 불가 |
| 후진·장애물 시험 | 당시 새 후진 소스의 실차 실행과 장애물 우회 성공을 입증할 기록 부족 | 성공 또는 실패를 확정할 수 없음 |

위 항목은 서로 다른 시험 구간의 관찰을 포함한다. 하나의 동일 시험에서 모두 발생한 결과로 합치지 않는다.

Home 차이의 기준점·시각은 원본 상태 파일로 재확인했다. 0.82m·151°는 등록 Home이 아니라 당시 활성 사용자 지정 Home과의 차이다. 등록 Home과는 약 0.60m·147° 차이이며, 어느 값도 완료 순간의 오차를 증명하지 않는다. [FTA 보고서 7절](PHYSICAL_FTA_REPORT_20261104.md)의 정정 근거를 참고한다.

### 3.2 병목 해석

기존 기록에서 A* 계산 자체는 약 **10~22ms**였다. 사용자가 체감한 긴 재계획 대기를 A* 탐색 시간만으로 설명하기는 어렵다. 20초 진행 실패 판정, 동작 취소·재시도, 입력 시각 불일치와 최종 출력 검사도 대기 시간에 관여했다.

11월 5일 추가 진단에서는 장애물 충돌이 없는 상황에서도 검사 시간이 제한을 넘으면 출력이 0이 되는 현상을 확인했다. 실제 AUTO 상태의 한 표본은 다음과 같다.

| 진단 지표 | 기록값 |
|---|---:|
| 출력 전 검사 경과 시간 | 68.694ms |
| 해당 검사의 계산 기한 | 50ms |
| 충돌 판정점 수 | 0개 |
| 계산된 최소 차체 여유 | 약 30.66cm |
| 정지 사유 | CONTROL_DEADLINE |

이 표본은 **통로가 막혀서 정지한 경우와 계산 지연으로 정지한 경우를 구별해야 함**을 보여준다. 웹 상태 표본에는 중복·누락이 있으므로 이 표본들로 전체 정지 발생률을 산출하지 않는다.

## 4. 변경 시스템 구성

### 4.1 현재 실행 배치

현재 확인한 운용 구성은 로봇과 PC의 역할을 분리한다.

~~~mermaid
flowchart LR
    subgraph PC["운용 PC"]
        W["재고 요청·임무·관제 웹"]
        P["저장 지도·AMCL·A*"]
        N["Nav2·경로 추종"]
        W --> P --> N
    end
    subgraph ROBOT["TurtleBot3 / Raspberry Pi"]
        S["라이다"]
        O["바퀴·IMU"]
        E["독립 EKF"]
        H["센서·위치 상태 감시"]
        M["20Hz 최종 출력 검사·중재"]
        K["OpenCR·모터"]
        C["후방 카메라"]
        O --> E
        S --> H
        E --> H
        H --> M
        S --> M
        E --> M --> K
    end
    E -->|"odom·TF"| P
    S -->|"scan"| P
    N -->|"시각·순서가 포함된 주행 명령"| M
~~~

- **로봇:** 센서 취득, EKF, 상태 감시, 최종 속도 중재 및 모터 출력.
- **PC:** 저장 지도, AMCL, A*·Nav2, 임무·재고 웹과 표식 확인.
- **공통:** 도메인 16, 2026-10-30 교실 지도, 후방 카메라 사용.
- **기존 진입점 유지:** 로봇의 기존 turtlebot16 스크립트를 사용하며 재생성하지 않았다.

### 4.2 주행·복구 변경

| 구분 | 변경 내용 | 목적 |
|---|---|---|
| 가까운 경로 추종 | RouteTrackingDWB와 경로 순서에 따른 국소 목표·추종 비용 적용 | 코너 목표를 먼저 향하며 경로를 벗어나는 동작 억제 |

## 6. 성능 차이

### 6.1 11월 5일 추가 개선 항목의 로봇 계산 시험

아래 수치는 **11월 5일 당일 최적화 전후**의 함수 수준 측정이다. 11월 4일 실차 계산 시간으로 소급하지 않는다.

이 수치는 추가 계산 성능 개선을 뒷받침하며, FTA의 I-11·I-12·P-01·M-11·M-12·R-01·X-01 종결 판정을 대신하지 않는다.

- 장비: 실제 로봇의 Raspberry Pi.
- 입력: 합성 360개 라이다 점, 이전·대기 입력을 포함하는 두 점군, 동일한 속도·불확실도 조건.
- 반복: 단계별 프로파일 30회.
- 변경 묶음: 배열 준비·변환 절감, 거리 하한 검사, 네이티브 기하 계산.
- 프로파일러를 사용했으며, 수집 당시 전체 CPU 부하와 운용 상태가 완전히 동일하게 통제된 실험은 아니다.

계산 입력과 호출 구성은 [변경 전 측정 스크립트](../benchmarks/physical_performance_report_20261105/profile_stages.py)와 [변경 후 측정 스크립트](../benchmarks/physical_performance_report_20261105/profile_prepared.py)에 보존했다. 이 스크립트의 계산 호출은 ROS 주행 명령을 발행하지 않는다.

| 측정 단계 | 최적화 전 중앙값 | 최적화 후 중앙값 | 처리 시간 감소 |
|---|---:|---:|---:|
| 요청 속도 제동 검사 | 4.271ms | 1.017ms | 76.2% |
| 측정 속도 제동 검사 | 14.771ms | 3.667ms | 75.2% |
| raw 충돌 검사 6회 묶음 | 10.111ms | 1.892ms | 81.3% |
| 최종 출력 제동 검사 | 4.015ms | 1.005ms | 75.0% |

**수치 해석**

1. 단계별 중앙값을 더한 값을 전체 출력 검사 또는 ROS 제어 지연의 실측값으로 쓰지 않는다.
2. raw 검사 6회 묶음의 중앙값을 6으로 나누면 약 **0.315ms/회**다. 이는 환산값이며 단일 호출 중앙값을 별도로 측정한 결과가 아니다.
3. 대화에서 안내한 “약 8ms”는 단계별 계산 시간의 대략적인 합을 설명한 값이다. 전체 ROS 제어 과정의 검증된 지연값으로 사용하지 않는다.
4. **전체 검사·센서 수신·명령 전달을 포함한 1ms 완료는 달성 또는 보장한 상태가 아니다.**

별도의 초기 벡터화 시험에서는 raw 검사 6회 묶음 중앙값이 **17.075ms → 5.252ms**로 감소했다. 이는 앞선 최적화 단계의 별도 시험이며, 위 표와 조건을 혼합해 추가 개선율을 산출하지 않는다.

| 최신 수정본 전체 회귀·Gazebo·반복 실차 임무 | 이번 보고서 작성 전 추가 실행하지 않음 | 전체 합격으로 표시하지 않음 |

185개와 75개는 각각의 검사 시행 결과다. 이를 중복 없는 전체 시스템 시험 260개로 합산하지 않는다. 별도 원시 pytest 로그가 없는 항목은 당시 도구 실행 결과의 전사 기록으로 보존했다.

기존 문서에 남은 전체 검사 **1,478개 통과·1개 실패 후 중단** 기록도 유효한 과거 이력이다. 이번 집중 검사 통과가 그 실패를 해결했다는 의미는 아니다.

## 8. 결과 및 종합 평가

### 8.1 확인된 개선

1. 경로 생성 외에 **출력 검사와 명령 전달 구조가 주행을 끊을 수 있음**을 식별했다.
2. 스캔·타이머의 중복 계산과 제어권 갱신 정체를 수정했다.
3. 계산 결과의 의미를 유지하면서 배열·후보 검사·C++ 가속으로 연산 부담을 줄였다.
4. 직진·선회·후진 속도와 가속을 구분하고, 경로 추종 및 복구 절차를 보완했다.
5. 수정본을 실제 로봇에 적용했으며, 사용자로부터 주행 개선 확인을 받았다.

### 8.2 최종 판정

**현재 단계는 “실차 주행 개선 확인”으로 평가한다.**

FTA 기준으로는 **사건별 원인·회복 검증의 종결이 완료되지 않았다.** 따라서 “기존 고장 원인을 모두 제거했다” 또는 “11월 4일 실패가 재발하지 않는다”는 판정을 내리지 않는다. 각 사건의 판정은 1.2절 추적표를 따른다.

다만 모든 섹터의 반복 완주, 장애물 배치 변화, 장시간 운용 및 정지 거리까지 검증한 “전체 시스템 성능 검증 완료” 단계는 아니다. 특히 전체 제어 과정 1ms, 실패율 감소율, 평균 배송 시간 및 위치 오차 개선율은 현재 근거로 산출하지 않는다.

이번 결과는 **필요한 검사를 유지하면서 실행 지연과 불필요한 반복을 줄이는 방식의 계산 성능 개선 및 현재 운용 개선 관찰**을 뒷받침한다. 이는 FTA에서 미확정으로 남긴 어제 고장 원인을 확정하거나 그 종결을 대신하는 결론이 아니다.

### 8.3 후속 검증 항목

| 항목 | FTA 또는 추가 개선 연계 | 권장 확인 내용 |
|---|---|---|
| 반복 왕복 | TE-01·R-01 | 동일 출발 조건의 Sector 2 왕복 및 1→2→3→Home 반복 횟수·완료 건수 |
| 장애물 운용 | P-01·R-01 | 추가·제거 시각, 국소 우회·후진·재계획 선택, 실제 재출발 여부 |
| 주행 연속성 | I-11·I-12·R-01 | 정상 주행 구간의 비의도 정지 횟수·지속 시간·정지 사유 |

위 표는 향후 계획이다. 보고서 작성 과정에서 로봇 또는 시뮬레이션을 다시 기동하지 않았다.

## 9. 운용 종료 상태

보고서 작성 전 사용자 요청에 따라 다음을 종료했다.

- 웹 비상정지 명령 후 최종 0속도 출력과 정지 확인 응답 확인.
- 로봇 브링업, EKF, 상태 감시, 최종 속도 중재, 라이다 및 후방 카메라 종료.
- PC의 주행 런치, AMCL·Nav2·계획·추종 노드 및 웹 서버 종료.
- 로봇 장치 점유 해제와 웹 8790·8791·8792 포트 비청취 확인.

시스템 재가동이나 추가 시험 없이 저장된 자료만으로 본 보고서를 작성했다.
