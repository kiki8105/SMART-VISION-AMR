# 실제 odometry 후진 이력 재생 — 2026-11-04

전체 웹 시험은 상자 제거 뒤에도 정지하여 **진단을 위해 중단**했습니다. 이 폴더는 그 실패 기록을 분석한 고정 입력 시험입니다. 실제 또는 Gazebo 후진 성공 판정이 아닙니다.

## 발견과 변경

- 실제 odometry 779개와 후진 검사 4시점을 보존했습니다. 지도 좌표 이력은 1/3/3/1개였지만, odometry에는 실제로 지나온 후방 구간이 있었습니다.
- 정지 중 지도 위치 변화 18.29mm에 비해 odometry 이동은 1.81mm였습니다. map 좌표 이력만 사용하면 일반적인 AMCL 보정으로 이력이 지워질 수 있습니다.
- 실제 10cm 뒤 지점의 과거 헤딩은 현재와 약 0.38rad 달랐습니다. 헤딩 숫자 일치 대신 실제 source 연속성을 확인한 odometry 이력과 현재 후진축의 좁은 통로를 검사합니다.
- 차체 반경 22cm, 기존 추가 여유, 원본 지도·미확인 영역·실측 장애물·기억 셀, 전체 후진 직선, 팽창 밖 끝점 및 목적지 도달 가능 조건은 유지합니다.
- source/수신 간격 0.75초 이상, source 시각 역행, frame 변경, 위치·방향 점프는 실제 이력을 폐기합니다. 단순 정지 때문에 공간 표본 간 시간이 길어져도 source가 계속 수신됐다는 증명은 별도로 유지합니다. 과거 지점을 새로 방문한 것처럼 시각을 바꾸지 않습니다.

## 재현

저장소 루트에서 실행합니다. ROS/Gazebo 실행은 필요하지 않습니다.

```bash
python3 benchmarks/driving_parameter_tuning_20261104/odom_trail_recovery/replay.py \
  --output /tmp/odom-trail-replay-new.json
```

결과 파일이 이미 있으면 덮어쓰지 않습니다. `results.json`에 원본 입력·지도·이전/현재 selector·odometry helper의 SHA256과 한계를 함께 기록했습니다. 이전 selector는 변경 직전 바이트 해시와 일치하는 소스입니다.

`actual_odom_input.json.gz`: 실제 source/수신 시각, frame, pose와 4개 검사 시점.
`recorded_audit.json`: 원래 이력·odometry·지도 보정 비교.
`extract_audit.py`: 원본 safety timeline이 있을 때 같은 감사 데이터를 다시 추출하는 도구.
