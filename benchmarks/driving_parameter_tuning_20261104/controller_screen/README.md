# DWB 고정 입력 파라미터 비교 — 2026-11-04

**실제 Nav2 controller에서 6개 설정 × 2개 입력을 비교했습니다. 폐루프 주행 합격이나 실차 완주 결과는 아닙니다.**

차체 반경 0.22m·footprint padding 0·Nav2 inflation 0.30m의 동일 기본 설정에서 다음 두 값만 변경했습니다.

- `FollowPath.route_horizon_distance`: 0.45 / 0.55 / 0.65m
- `FollowPath.BaseObstacle.scale`: 0.02 / 0.04

`ObstacleFootprint.scale=0.02`, 속도·가속도·차체 크기와 다른 critic 값은 유지했습니다. 원래 재생기의 디버그 평가를 사용하므로 모든 critic을 평가하고 short circuit을 끕니다. 이 상태의 계산 시간은 실제 운용 주기의 성능 측정값으로 사용하면 안 됩니다.

Nav2의 `ObstacleFootprintCritic::getScale()`은 설정값에 costmap 해상도를 곱합니다. 따라서 설정의 `0.02`는 5cm 지도에서 평가 기록의 `scale=0.001`로 나타납니다. 래퍼가 값을 변경한 것이 아닙니다.

**추천 1: 기존 `(0.55, 0.02)` 유지.** 이 두 입력에서 더 나은 선택을 만든 조합은 없었습니다. 추가 폐루프 후보가 필요하면 `(0.45, 0.02)`를 동등성 후보로 비교할 수 있으나, 선회·추종·완주 성능의 개선 증거는 없습니다. 장애물 비용만 0.04로 올릴 근거도 이번 결과에서는 얻지 못했습니다.

## 한계와 시작 구간

- 입력은 실차 사고 녹화에서 추출한 고정 scan/TF/odom/path와 합성 코너입니다. 로봇은 움직이지 않으며, 출발 준비·웹·AMCL·memory·mux·최종 표식 정렬을 포함한 시스템 시험이 아닙니다.
- local costmap은 같은 scan으로 다시 구축했습니다. 기록된 costmap 전체의 시간 이력을 재생한 결과가 아닙니다.
- 녹화 입력은 모든 조합에서 시작 직후 `Resulting plan has 0 poses in it` 로그와 **trajectory가 0개인 빈 평가 3회**가 나온 뒤 정상 평가로 바뀌었습니다. 이것은 충돌로 모든 후보가 거부된 평가와 구분했습니다. 비어 있지 않은 평가에서 전부 거부된 경우는 0회입니다. 이 시작 구간을 출발 준비 성공으로 간주하지 않습니다.
- action 요청 후 관측 시간을 2초로 설정했습니다. 시작 준비·콜백 처리·취소 시간을 포함한 전체 프로세스 시간과 평가 개수는 실행마다 달랐습니다.
- 갑작스러운 회전 재발이 이 두 고정 입력에서 관측되지 않았다는 결과입니다. 다른 위치·동적 장애물·누적 위치 오차에서 재발하지 않는다는 보장은 아닙니다.
