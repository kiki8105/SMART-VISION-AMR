# 경로 생성 파라미터 오프라인 비교 — 2026-11-04

**우선 폐루프 시험 후보: `preferred_clearance: 0.45`, `clearance_penalty_gain: 2.2`.** 기준 `.45 / 1.5`보다 7개 방향별 경로의 평균 벽 여유가 모두 유지되거나 증가했고, 합산 길이는 1.71% 증가했습니다. 실제 주행 성능의 개선이나 최종 채택을 의미하지 않습니다.

## 범위와 입력

- 9조합 × 14개 고정 입력 = **126개 계획**. 모두 경로 생성 및 연속 경로 기하의 정적 지도·실제 상자 비접촉 조건을 충족했습니다.
- 실제 `classroom_20261030_cleaned` 지도와 웹이 사용하는 `aruco_classroom_markers_20261030.yaml` 좌표를 사용했습니다. 두 순서 `0→1→2→3→0`, `0→1→3→2→0`에 필요한 7개 방향별 구간을 각각 새로 계획했습니다. 연속 임무의 이동·기억 변화·취소를 실행한 시험은 아닙니다.
- 녹화 상자 장면 3개를 각각 전역·국소 계획으로 검사하고, 별도 29 observed / 9 memory 시작 간선 인증 장면 1개를 전역 계획으로 추가했습니다. 과거 `.25m` reserve 장면도 **현재 `.20m` 설정으로 다시 계획**했습니다.
- 모든 조합의 차체 반경 `.22m`, A* 정적 팽창 `5 cells`, 지도 해상도 `.05m`, reserve `.20m`, 실제 관측·기억·정적/미지 영역의 hard 차단과 인증 간선 제약을 유지했습니다.
- 생산 `plan_to`와 `_try_local_detour`를 ROS 노드 생성 없이 테스트 하네스로 호출했습니다. 신선한 scan/odom/TF·정상 위치·자동 제어권을 가정했습니다. **실제 pre-arm, DWB 추종, 실제 차체 회전, Wi-Fi/센서 지연, ArUco 검출 및 폐루프 완주는 검사하지 않았습니다.**
- 입력 파일 전체 SHA-256, 작업 HEAD, 좌표, 경로점 및 계획 진단은 [planner_screen.json](planner_screen.json)에 저장했습니다. 실행 시점 소스 해시를 기준으로 해석해야 합니다.

## 후보 판단

- **`.45 / 2.2`를 먼저 시험합니다.** 기준보다 내부 평균 여유가 약 **0.87cm** 증가합니다. 0→1은 동일하고 나머지 6구간은 약 0.85~1.22cm 증가했습니다. 길이 합은 1.71% 증가했습니다. 경로 각도 변화는 약 0.386rad(22.1°) 증가했으므로 선회가 줄었다거나 추종이 더 부드럽다고 단정할 수 없습니다.
- `.55 / 2.2`는 합산 길이 증가가 0.93%로 작지만 2→3, 3→0, 3→2의 평균 여유가 각각 약 0.32, 0.61, 0.13cm 감소합니다. 따라서 **균일한 구간 개선을 우선하는 후보에는 `.45 / 2.2`가 적합**하며, `.55 / 2.2`는 별도 비용 절충안으로만 남깁니다.
- 박스 3장면과 별도 인증 장면에서 우선 후보의 실제 상자 최소 여유는 기준보다 유지되거나 증가했습니다. 신규 관측이나 실제 이동 중 시작점 막힘 문제까지 해결했다는 결과는 아닙니다.
