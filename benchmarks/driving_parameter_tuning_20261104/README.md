# 주행 파라미터 비교 — 2026-11-04 중간 결과

**최적 조합은 아직 확정하지 않았습니다.** 아래는 후보 선별 결과와 실제 가제보 폐루프 결과를
구분한 기록입니다. 고정 입력에서 경로가 생성되거나 controller가 전진을 선택해도 전체 임무 합격은 아닙니다.

최종 비교는 **최신 공통 코드의 정식 실차 YAML을 기준으로 먼저 실행하고, 한 번에 파라미터 하나만**
바꿉니다. 물리 반경·안전 조건·시험기·입력 조건을 고정하고 소스/설정 해시를 함께 남깁니다.
개별 효과를 확인한 뒤에만 조합 후보를 비교합니다. 아래의 다변수 오프라인 탐색은 후보 선별용입니다.

기본 장애물 시험기는 생성된 경로에 맞춰 상자 위치·이동 방향을 선택합니다.
따라서 같은 시험기라도 경로 비용을 바꾸면 장애물 장면이 달라질 수 있습니다.
gain 2.2 실행도 기준 실행과 상자 좌표·방향이 달라 **같은 유형의 시험이지 고정 장면 A/B는 아닙니다.**
후속 인과 비교에는 같은 장애물 장면과 동일한 충돌·실제 경로 차단·우회 검증을 함께 유지해야 합니다.
[후속 고정 장면 결과](FIXED_SCENE.md)에는 유효한 3회 실행의 복구 실패와 2회 입력 무효를
구분했습니다. 실제 관측·기억의 가상 reserve 및 시작점 인증 문제를 수정한 뒤에도
후진 선택 조건에서 멈추는 현상이 남았습니다. 파라미터만으로 해결된 것으로 처리하지 않습니다.

## 복구 정책 교체

[`recovery_episode.py`](../../ros2_ws/src/smart_vision_amr/smart_vision_amr/recovery_episode.py)가
같은 목표·지도의 **국소 우회 → 정지 확인 → 후진 → 전체 계획 → 추종/장애물 대기**를 소유합니다.
기존의 전역 재계획 우선 분기·복구 전 실패 횟수 차단·동일 입력 주기 재탐색은 새 활성 경로
복구에서 사용하지 않습니다. 후진 불가가 검증되면 현재 정지 자세에서 전체 계획을 수행합니다.

전체 계획에도 경로가 없으면 실제 자유 공간·확정 기억의 해제·확인된 움직이는 장애물 변화·
명시적 새 임무 입력을 기다립니다. 반복된 수신 시각이나 TTL 소멸은 장애물 제거 증거가 아닙니다.
이미 한 번 소비한 자유 공간 증거로 같은 실패 주기를 계속 열지도 않습니다.
기존 경로가 다시 열리면 신선한 충돌 검사 후 같은 경로를 재사용할 수 있습니다.

액션의 경로 stamp와 후진 episode ID를 함께 확인해 이전 성공·실패·취소 응답이 현재
복구를 종료하거나 실패 기억을 새 경로에 추가하지 못하게 합니다. 이것은 좌표 임계값 완화와
구분하는 코드 수정이며, 아래의 이전 파라미터 실험 결과를 새 코드의 합격으로 승계하지 않습니다.
새 코드의 폐루프 판정은 별도 실행으로 남겨야 합니다.

| 고정하는 항목 | 값·판정 |
|---|---|
| 차체·지도 | 반경 0.22m, 5cm 지도, A* 정적 팽창 5셀 |

| 변경 후보 | Nav2 inflation, A* 중앙 선호 비용, 선회 미리보기·감속 여유, controller 추종 지평 |

실제 라이다·위치 신뢰도·pre-arm·도착 판정을 완화해 후보를 통과시키지 않습니다.
현재 정식 기준값은 inflation 0.22m, 중앙 선호 0.45m/강도 1.5, 감속 여유 0.15m,
미리보기 1.0m, 추종 지평 0.55m입니다. 기준 파일은
`classroom_demo_operator_20261104.yaml`과 `classroom_hardware_nodes.yaml`입니다.
정적 지도의 5셀은 원형 25cm가 아닌 사각 팽창이며, 대각선에서 추가 차단이 더 큽니다.
실시간 관측과 확정 기억은 동일한 원형 차체 기반 계산을 사용합니다. 기억 확정만으로 장애물이 더 커지지 않습니다.
[사각/원형 기하 감사](geometry_audit/README.md)는 이 차이와 최근 시작점 실패를 구분해 기록했습니다.
[후진 거절 감사](recovery_audit/README.md)는 실제 기록과 합성 직선 이력을 구분해 복구 조건을 점검했습니다.

## 3. 감속 여유: 실제 속도 상한 함수의 고정 경로 선별

[braking_screen.json](braking_screen.json)은 미리보기 0.6/1.0/1.2m × 감속 여유
0.15/0.25/0.35m × 경로 3개, 총 27조건을 비교했습니다.
이번 세 경로에서는 같은 감속 여유의 미리보기 값만 바꿔도 속도 상한 결과가 같았습니다.

|---:|---:|---:|---:|---:|
| 0.15 기본 | 0.89 | 0.79 | 0.84 | 21.62 |

시작 위치는 각 경로를 따라 진행한 거리입니다. 여유를 10cm 늘리면 약 10cm 먼저 감속했습니다.
0.22→0.12m/s 감속의 설정 감속도 0.10m/s²는 유지했습니다.
이론 시간은 속도 상한을 그대로 따라간 하한 추정이며 출발 가속·실제 추종·표식 정렬·대기를 포함하지 않습니다.
0.25m의 가제보 탐색 조합은 실행했지만 합격하지 못했습니다. 이전 0.15m 기록과 코드 버전이 달라
인과적 A/B 비교가 아닙니다. 최신 공통 코드로 정식 0.15m 기준 실행부터 다시 확보한 뒤
다른 값은 고정하고 0.25m만 변경해 비교합니다.
