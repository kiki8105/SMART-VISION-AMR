# 사각 팽창 5셀과 원형 22cm — 오프라인 기하 감사

**사각 팽창의 대각선 추가 차단은 확인했지만, 최근 시작점 정지를 이것만으로 설명하거나 해결하지는 못했습니다.**
실행 중인 주행 정책·YAML·시험기는 변경하지 않았습니다.

## 팽창 의미

`occupancy_to_grid(..., inflation_cells=5)`와 기억용 `inflate_cells(..., 5)`는
Chebyshev 사각 팽창입니다. 라이다 실시간 레이어는 `inflate_cells_footprint(..., .22/.05)`로
원형 차체와 두 셀의 전체 면적을 고려합니다. 두 방식은 서로 다릅니다.

5cm 지도에서 고립된 장애물 셀 하나의 차단 영역은 사각 방식 **121셀**, 원형 방식 **101셀**입니다.
원형보다 추가 차단되는 20셀은 대각선 모서리에 있습니다.

| 셀 오프셋 | 셀 중심 간 거리(cm) | 두 셀 전체 면적의 최소 거리(cm) | 사각 5셀 | 원형 22cm 전체 셀 |
|---|---:|---:|---|---|
| (5, 0) | 25.00 | 20.00 | 차단 | 차단 |
| (5, 3) | 29.15 | 22.36 | 차단 | 허용 |
| (5, 5) | 35.36 | 28.28 | 차단 | 허용 |
| (6, 0) | 30.00 | 25.00 | 허용 | 허용 |

따라서 “5셀은 22cm에서 3cm 올린 값”은 축 방향의 첫 허용 셀에 대한 설명입니다.
전방향의 추가 여유가 3cm뿐이라는 뜻은 아닙니다. 차체 반경에 팽창 거리를 다시 더하는 것도 아닙니다.

## 보관 장면과 최신 baseline 대조

정적 지도·기억을 각각 사각/원형 마스크로 바꾼 네 가지 오프라인 대조를 수행했습니다.
실제 라이다·기억 셀, 원본 occupied/unknown, 차체 22cm는 유지했습니다.
가상 occlusion 깊이는 기하 효과 분리를 위해 제외했고 시작점 예외·탈출 증명도 적용하지 않았습니다.
이는 전체 생산 planner의 복구 동작을 그대로 재생한 시험이 아닙니다.

| 장면 | 사각 기억의 시작점 차단 | 원형 기억의 시작점 차단 | 결과 |
|---|---|---|---|
| 보관 첫 관측·두 번째 관측 | 없음 | 없음 | 정적 원형 마스크에서 경로가 짧아짐 |
| 보관 기억 12셀 장면 | 없음 | 없음 | 정적 사각 유지 시 기억 원형만 변경하면 경로 77→75셀 |
| 보관 certified-start 초기 | 없음 | 없음 | 라이다 시작 셀 차단이 남음; 생산 시작점 증명은 이 대조에서 제외 |
| 보관 certified-start 후속 기억 | 있음 | 있음 | 원형 기억으로 바꿔도 시작점 차단 유지 |
| 최신 baseline 첫 NoPath | 없음 | 없음 | 실제 진단은 **가상 기억 reserve**에서 먼저 차단 |
| 최신 baseline 약 10.7초 뒤 | 있음 | 있음 | 실제 기억 레이어에서도 시작점 차단; 원형 변경만으로 해소되지 않음 |

생성된 대조 경로 12개는 모든 연속 선분을 원본 occupied/unknown·라이다·기억 셀의
실제 사각형과 독립 계산했습니다. 최소 차체 여유 **4.51cm**, 실제 상자 여유 **5.93cm**이며 모두 비접촉입니다.
경로가 없는 장면에 대해서는 통과·완주를 주장하지 않습니다.

최신 baseline 첫 진단은 wall epoch `1793798470.678023`, 시작 셀 `(34,93)`입니다.
다음 진단 `1793798481.33909`에서 기억 셀 사각형 대비 추정 pose 여유는 약 **1.57cm**였지만,
가제보 truth를 같은 지도 셀에 대조하면 약 **−0.86cm**였습니다. 실제 상자와 truth의 여유는 **7.24cm**입니다.
즉 실제 상자·지도에 투영된 셀·위치 추정은 같은 기하가 아니므로, 상자 공간이 넓다는 이유만으로
기억 셀 차단을 지워도 된다고 결론 내릴 수 없습니다.

관측 셀은 독립 recorder의 직전 표본이라 planner의 원자적 상태 dump와 완전히 일치하지 않습니다
(첫 표본은 관측 22셀, planner 로그는 23셀). truth 표본 간격과 기억 갱신 시각도
[results.json](results.json)에 남겼습니다. 보관 후속 장면에는 동기 pose가 없어 셀 중심만 사용했습니다.
이 한계 때문에 최신 전체 장면의 엄밀한 재현 합격으로 취급하지 않습니다.
