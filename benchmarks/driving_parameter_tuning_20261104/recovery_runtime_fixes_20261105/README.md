# 2026-11-05 주행 런타임 추가 수정

**최종 상태: 사용자 요청으로 시험 중도 중단.** 추가 주행 시험은 시작하지 않았습니다.
최종 전체 Python 검사는 **1,478개 통과·1개 실패 후 중단**했으며 나머지는 미실행입니다.
실패는 metric connector 기능 fixture의 test-only 100ms 시간 예산 조건입니다.
중단 후 재검사하거나 예산을 완화하지 않았습니다.
[원본 중단 결과](checks_user_interrupted.json)와 [전체 로그](pytest_user_interrupted.log.gz)를 보존합니다.
최신 수정 후 Gazebo·실차 완주를 검증하지 않았습니다.
[변경 요약·실차 터미널 명령](../../../docs/PHYSICAL_RUN_20261105.md)을 참고하세요.

이전 `1ee7fcd`의 실패 기록을 보존하고, 정체·경로 이탈·느린 제동의 원인을
실제 코드에서 수정한 단계입니다. 이전 시험 결과는
[원본 8개 실행](../physical_transfer_20261105/final_matrix.json)에 있습니다.
시뮬레이션과 기록 재생은 실차 재시험을 대신하지 않습니다.

## 정지 판정의 비교

설정 감속도를 0.4에서 0.15m/s²로 바꾸면 0.22m/s 진입의 계산상 허용 정지
거리가 약 11.55cm에서 21.63cm로 커집니다. 이 변경만으로 제동 문제가 해결됐다고
판정하지 않습니다. 새 로그에서도 기존 0.4 기준의 이동량을 별도로 비교하고,
실제 상자–차체 여유 2cm·정지 명령 0.25초·정지 중 방향 변화 0.12rad 기준은 유지합니다.

검사기의 전방 거리 변환도 수정했습니다. 원래 Waffle의 짧은 전방 외곽용 13.2cm를
22cm 원형 복사 모델에 그대로 쓰지 않습니다. 실제 fixture의 ray sensor 위치
(-6.4cm)와 원형 반경으로 계산하면 센서부터 전방 끝은 28.4cm입니다. 새 원형
시험은 이 값으로 더 엄격하게 검사하며, 이전 기록과 원래 판정은 덮어쓰지 않습니다.

## 테스트 기대값 수정 근거

[원래 전체 검사 실패](pytest_initial_failed.log.gz)의 raw-capsule `yaw=π/2` 사례는
실제 raw 장애물 `(0.55, 1.85)`를 무시한 통과가 아니라, 새 국소 후보의 독립
scan/visibility 쌍이 없는 `LOCAL + SENSOR_HOLD`였습니다. 기하 검색이 시간 안에
끝나지 않으면 같은 입력도 `STOP_PROOF`가 되므로, 이전의 한 단계 강제 기대는
호스트 처리 시간에 따라 실패했습니다. 별도 진단에서 검색 호출에만 300ms를 주면
767확장·54.88ms 뒤 후보 검증에 도달하지만, raw/projected cache가 모두 비어 있어
`coherent_raw_scan_input_pending`으로 nonempty 경로를 발행하지 않았습니다.
이 진단 예산은 생산 60ms 성능 통과가 아닙니다.

원래 hit·좌표·차체와 생산 설정은 그대로 두고, 실제 더 새 raw 수신과 독립 visibility
callback 후 대기가 풀리는지 검증하도록 세 방향 회귀를 수정했습니다. 가능한 새
우회 경로는 전체 연속 구간에서 원래 raw point와 그 원본 점유 사각형으로부터
22cm 이상 떨어져야 합니다. 실제 후진 정지 증명이 없으면 `STOP_PROOF`에 머물고,
확인된 물리 장애물은 controller 재시도 예산으로 바뀌지 않습니다. 파일의 8개 검사는
모두 통과했습니다. 런타임의 충돌·입력 허용 조건은 이 테스트 수정으로 바꾸지 않았습니다.
